# T20 — Sticky prompt

## Goal
While a long assistant reply is being read, keep the user prompt that started that turn pinned at the top of the transcript. Clicking it returns to the exact start of that turn.

## Files to change
- New `src/core/prompt-navigation.ts` — pure prompt extraction/active-index helpers.
- New `components/prompt-navigation.tsx` — client provider + `StickyPrompt` (exports hooks/components reused by T21).
- `components/chat.tsx` — add prompt anchors to user rows; mount provider/sticky row inside `<Conversation>`.
- New `tests/prompt-navigation.test.ts`.

## Data / API shape
```ts
export interface PromptEntry {
  id: string;          // native user message id
  anchorId: string;    // `prompt-${id}`
  text: string;        // first text parts, whitespace-collapsed; "Image" if image-only
  index: number;       // index in LhViewMessage[]
  hasReply: boolean;   // an assistant message exists before the next prompt
}
export function promptAnchorId(messageId: string): string;
export function isPromptMessage(m: LhViewMessage): boolean;
export function promptEntriesOf(messages: readonly LhViewMessage[]): PromptEntry[];
export function activePromptIndex(tops: readonly number[], viewportTop: number): number; // last top <= viewportTop, else -1
export function promptLabel(text?: string): string;
```
`isPromptMessage`: `role === "user"`, has text or image part, and has none of `data-probe-handoff`, `data-subagent-artifact`, `data-subagent-aborted`. Data-only markers, compaction dividers, practice markers and plugin submissions are not prompts. `hasReply` is computed from the next prompt entry (or end of array), ignoring data-only user markers.

Provider API consumed in chat:
```ts
<PromptNavigationProvider entries={promptEntries} scopeRef={sessionFindScopeRef}>
  {/* sticky row + ConversationContent + T21 rail */}
</PromptNavigationProvider>
```
It calls `useStickToBottomContext()` internally, reads `scrollRef`/`stopScroll`, and exposes `jumpTo(index)` via context. Do not duplicate the scroller ref: reuse `sessionFindScopeRef` as the scope passed to `scrollSessionTarget`.

## UI / UX design
- Mount `PromptNavigationProvider` just inside `<Conversation>` (line ~1800), wrapping `ConversationContent`. Keep `SessionMessageNavigation` and `TranscriptElementReporter` where they are.
- Compute `promptEntries` with `useMemo(() => promptEntriesOf(messages), [messages])` in `Chat`.
- Give each rendered user prompt row `id={promptAnchorId(m.id)}` and `data-prompt-id={m.id}` in the `data-testid="user-message"` branch (~1915). No other row gets that id.
- `StickyPrompt` is the first child of `ConversationContent`: `sticky top-0 z-20 h-9 shrink-0`, `bg-background`, `border-b border-border`, `px-6` (`px-4` under 640px). Always reserve the 36px row once `entries.some(e => e.hasReply)`; use `visibility: hidden` when inactive so switching prompts never shifts content. No glass, blur, shadow or fixed positioning.
- Row grid: `grid-cols-[3ch_minmax(0,1fr)_auto]`; left `font-medium uppercase text-muted-foreground text-xs` label `You`; middle `truncate font-ui text-xs text-foreground` with `title={full text}`; right `ArrowUpIcon` (`size-3.5 text-muted-foreground`). Whole row is one native `<button type="button">` with `aria-label="Jump to your prompt: <full text>"`.
- Interaction: `hover:bg-accent`, `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring`; Enter/Space come from the native button. Click calls `jumpTo(activeIndex)` → `scrollSessionTarget(anchor, scopeRef.current, { scrollRef, stopScroll })` (existing helper, 16px top offset).
- Active detection: passive `scroll` listener on `scrollRef.current`, recomputed in a single `requestAnimationFrame`; also recompute on `messages` change and on `ResizeObserver` of the transcript column. Threshold is `scroller.getBoundingClientRect().top + 4`. Visible only when `activeIndex >= 0`, `entries[activeIndex].hasReply`, and `scrollTop > 8`. Never auto-scroll when the active prompt changes.
- Narrow screens: same row, padding `px-4`, text still truncates to one line; no tooltip or second rail. Side panel remains untouched.
- Empty/loading/error: no entries with `hasReply` → reserved row is hidden; streaming placeholder does not create an entry; an error after a prompt keeps that prompt active; `id` missing → no anchor → row hidden rather than throwing.

## Edge cases
- Consecutive user prompts: the later one wins once it crosses the threshold; each keeps its own anchor/jump.
- Image-only prompt label is `Image`; attachments remain on the original row, not in the sticky row.
- Duplicate legacy message ids: de-duplicate by native id, keep the first entry; the DOM id must stay unique.
- Hash navigation / Session Find still work; both may call `stopScroll`, and sticky detection must not call `stopScroll` itself.
- Subagent steer cards and probe-handoff dividers never pin.

## What must NOT change
- Message ordering, wording, `PathText`, markdown/citation rendering, dock, side panel, session find, plugin shortcut handling.
- No new persisted state, no router/hash writes, no changes to `scrollSessionTarget` or `Conversation` defaults.

## Tests to add (`tests/prompt-navigation.test.ts`)
- `promptEntriesOf` keeps text/image user messages and skips data-only, probe-handoff and subagent markers; labels collapse whitespace; image-only → `Image`.
- `hasReply` is false for a trailing user prompt and true only when an assistant message follows before the next prompt.
- `activePromptIndex` picks the last anchor at/above the viewport top, returns -1 for none, and handles unsorted input by using the supplied order.
- `promptAnchorId` is stable and idempotent-looking (`prompt-${id}`); `promptLabel` truncates whitespace and defaults.
