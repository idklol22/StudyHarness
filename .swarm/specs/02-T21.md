# T21 — Prompt rail

## Goal
Add a slim right-edge rail with one tick per user prompt. Hover/focus reveals the prompt text; click/keyboard jumps to that prompt. Reuse T20's prompt extraction, active index and jump helper.

## Files to change
- `src/core/prompt-navigation.ts` — add pure tick-position helpers.
- `components/prompt-navigation.tsx` — add exported `PromptRail` and consume the T20 provider context.
- `components/chat.tsx` — mount `<PromptRail />` inside the T20 `PromptNavigationProvider` in `<Conversation>`.
- `tests/prompt-navigation.test.ts` — extend with position/clamp cases.

## Data / API shape
```ts
export function promptTickTop(index: number, count: number): number;    // percent 0..100; count<=1 → 50
export function promptTooltipTop(index: number, count: number): number; // percent clamped to 8..92
```
Both helpers clamp `index` to `[0, count - 1]` before computing, and return 50 when `count <= 1`. `promptTooltipTop` additionally clamps the final percent to `[8, 92]`.
`PromptRail` reads `entries`, `activeIndex` and `jumpTo(index)` from `usePromptNavigation()` (the T20 context). It does not recompute prompts or touch the scroller directly. Ticks are per `entries` item, including prompts with `hasReply === false`; only `activeIndex === i` renders the highlighted state.

## UI / UX design
- Render one `<div data-testid="prompt-rail" aria-label="Prompt navigation" role="group">` as an absolute sibling of `ConversationContent` inside `<Conversation>`: `pointer-events-auto absolute inset-y-3 right-1 z-20 hidden w-4 min-[900px]:flex items-center`. Do not add a second scroller. `z-20` sits below the side panel (`z-40`) and tooltip (`z-30`).
- Each tick is a 16px-wide, 12px-tall hit area positioned with `top: ${promptTickTop(i, n)}%` and `-translate-y-1/2`. Inside: a centered 8px × 2px line; inactive `bg-muted-foreground/50`, hover/focus `bg-foreground`, active `h-0.5 w-3 bg-foreground`. No rounded pill, no background surface on the rail itself.
- Tooltip: one `span` per tick, `pointer-events-none absolute right-6 z-30 hidden w-64 max-w-[min(16rem,calc(100vw-2rem))]`, `bg-popover text-popover-foreground border border-border px-2 py-1 font-ui text-xs leading-snug`, `line-clamp-2 whitespace-normal`, `top: ${promptTooltipTop(i, n)}%`, `-translate-y-1/2`. Show on `group-hover/tick` and `group-focus-within/tick`; `title={entry.text}` supplies the full browser tooltip.
- Buttons: native `<button type="button">`, `aria-label="Prompt N: <full text>"`, `aria-current={active ? "true" : undefined}`. Focus ring `focus-visible:ring-2 focus-visible:ring-ring focus-visible:outline-none`. Enter/Space calls `jumpTo(i)`; ArrowUp/ArrowDown move focus to the previous/next tick without jumping; Home/End move focus to first/last. Out-of-range arrows are ignored (no wrap).
- Active index comes from T20's scroll listener; update the highlight only, never call `stopScroll` from the rail. `jumpTo` reuses `scrollSessionTarget` so sticky-bottom is released before the jump.
- Empty/loading/error: zero entries → render nothing; one entry → tick at 50%; `activeIndex === -1` → no highlight; newly streamed prompts appear on the next `messages` change. No separate loading or error state.
- Narrow screens: `hidden` below 900px; the T20 sticky prompt remains the fallback. At 900px+ the rail sits in the transcript's existing `px-6` gutter and does not shrink `ConversationContent`.

## Edge cases
- Many prompts (>60): ticks keep 2px height and may visually cluster; do not virtualize or scroll the rail. Tooltip top is clamped to 8–92% so it never leaves the transcript.
- Image-only prompts show `Image` in the tooltip and a full label in `aria-label`.
- Duplicate legacy ids: T20 de-duplicates; the rail must not introduce a second tick for the same id.
- Side panel open: rail stays at the transcript column's right edge, not the window edge; tooltip stays left of the rail, never over the panel.
- Session Find highlights and hash jumps may run at the same time; rail only reflects `activeIndex`.

## What must NOT change
- T20's sticky row, `activePromptIndex`, anchor ids, `scrollSessionTarget`, `Conversation`/`ConversationContent` defaults, session find, dock, side panel, plugin shortcut scope.
- No new global keyboard shortcut; arrow-key handling is local to a focused tick only.
- No persisted rail state, no drag/resize affordance, no per-message bubbles.

## Tests to add (`tests/prompt-navigation.test.ts`)
- `promptTickTop(0,1) === 50`; evenly spaced for `n > 1`; first 0, last 100; negative index clamps to first, past-end index clamps to last, `count <= 0` returns 50.
- `promptTooltipTop` clamps the first/last tick to 8/92 while middle ticks use the exact tick percentage, including `count <= 1` → 50.
- A static render test (optional, linkedom) asserts one button per entry and `aria-current` on the active index only.
