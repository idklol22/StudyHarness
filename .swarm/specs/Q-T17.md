# Q-T17 — Tile chats (needs owner decisions)

## Status
Too unclear to build without guessing. No implementation spec; do not start this task until the owner answers the questions below.

## What the code shows
- `components/chat.tsx` mounts one chat surface: a single `<TopBar>`, `<Conversation>` with `SessionFind`/`SessionMessageNavigation`, one `<DockOverlay>`, plugin surfaces keyed to one `chatId`, and one `<SidePanel />` sibling (`~1655–1800`, `~2308`).
- `SidePanelProvider` and `panelReducer` are explicitly keyed by a single `chatId` (`components/panel/side-panel.tsx`, `components/panel/panel-store.ts`); panel items are persisted in `sessionStorage` under `lh.panel.items.<chatId>`.
- `ChatActionsContext`, `CitationActionsContext`, `JobsContext`, `useChatSession`, the composer, dock, plan popup and session-find scope are all single-session scoped.
- Routing is `/chat/[chatId]`; there is no multi-chat container, tile store, or drag/resize layout primitive to reuse. `data-layout=tiles|flat` exists only in `.swarm-THEME-BRIEF.md` as a future theme hook, not in this repo's CSS.

## Questions for the owner
1. **Entry point and lifecycle.** What opens tile mode: a new button in the current chat's top bar, a sidebar context-menu item, a drag of a chat from the sidebar, or a dedicated `/tiles` route? What closes it, and does the original single-chat view stay mounted underneath?
2. **Which chats are tiled.** Does tile mode show (a) the current chat plus the N most recently viewed chats, (b) chats explicitly picked by the user from a picker/sidebar, or (c) all chats in the current subject/topic? What is the initial count: 2 or 3? What is the hard maximum?
3. **Adding/removing/reordering tiles.** How does the user add a fourth chat when 3 are shown, remove one, and reorder them? Is order persisted across reloads, and where (`localStorage`, `sessionStorage`, URL query, or not at all)?
4. **Resize semantics.** "2–3 columns, resizable" needs exact rules: drag-only dividers, or preset 50/50 and 33/33/33 buttons too? Minimum tile width in px, what happens below it, and is the layout vertical-stack fallback on narrow screens or a horizontally scrollable strip? Which storage key holds the column fractions?
5. **Focus/keyboard/swipe.** `Ctrl+Alt+←/→` should move between tiles — does that mean move focus only, or also scroll/switch the active composer? What counts as "horizontal swipe" in this desktop-first app: trackpad horizontal wheel, touch swipe, or both? Should a swipe change focus, reorder tiles, or page through a hidden overflow? Which existing `kbdEventForAction` registry entry owns the shortcut (or should a new one be added)?
6. **Side reader and popup surfaces.** With several chats open, is there one shared side panel for the focused tile, or one panel per tile? Where do `CitationPill`, `show_figure`, `SelectionToolbar`, `SessionFind`, plan popup and plugin panels mount? If shared, what happens to an open reader when focus changes?
7. **Per-tile chrome and state.** Does every tile get its own `<TopBar>` (title, rename, phase chip, Files, Plan, plugin actions) and its own `<DockOverlay>`, or do tiles share one composer that sends to the focused chat? Are busy/streaming indicators per tile? Can two tiles run a turn at the same time?
8. **Identity and collisions.** If the same `chatId` appears in two tiles, is it de-duplicated? How are DOM ids such as `message-<id>` and `data-testid` values namespaced so Session Find, hash links and plugin input scopes do not jump in the wrong tile?
9. **Acceptance test shape.** For node:test, which pure pieces should be extractable (tile-list reducer, layout fractions, active-tile rotation) and what are the exact invariants to assert? Confirm that a browser-only verification is acceptable for drag/swipe.

## Suggested next step
Answer 1–3 first; they determine the component tree. Once those are fixed, a spec can pin the remaining numbers and event wiring without guessing.
