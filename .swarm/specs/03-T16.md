# T16 — Clickable file refs

## Goal
Make agent citations of library files/pages clickable and open the exact material at that page in the side reader. Give the agent one canonical citation format in both the system prompt and tool output.

## Files to change
- `src/core/study/doctrine.ts` — export the canonical format strings; include them in `studyInstructions` for `teach` and `plain` without breaking the existing 6k cap.
- `src/agent/study-chat-prompt.md` — use the same canonical wording as the study block.
- `src/server/study-agent.ts` — append the short cite hint to `study_context` and `study_material` tool results.
- `components/panel/side-panel.tsx` — add a visible focus ring to `CitationPill`; no other UI change.
- New `tests/study-citations.test.ts`; keep `tests/chat-side-panel.test.ts` green.

## Data / API shape
Already in place; do not invent a new token:
- `CitationMaterial { id, fileName, pageCount, title? }` (`components/panel/citations.ts`).
- `findCitations(text, materials)` matches `(name, p. N)`, `(name, pp. N-M)` and `(name p. N)`; first page of a range wins; unknown names and out-of-range pages stay plain text.
- `linkCitations` rewrites matches outside fenced code to inline-code tokens `lh-cite|<encoded id>|<page>|<label>`; `MarkdownCode` swaps those for `CitationPill`; `CitationPill` calls `panel.openMaterial(materialId, page)`.
- `panelReducer` bumps `nonce` on every open so an already-mounted reader jumps to the new page.

New pure exports:
```ts
export const STUDY_CITATION_FORMAT =
  'Cite library facts inline as "(exact file name, p. N)" with the 1-based PDF page, e.g. "(Lecture 3.pdf, p. 12)". ' +
  'For a range use "(Lecture 3.pdf, pp. 12-14)". Use the file name from the Materials list; never invent a name or page.';
export const STUDY_TOOL_CITE_HINT =
  'Cite any fact from this output as (exact file name, p. N) using the PDF page shown here.';
```
`studyInstructions` pushes `STUDY_CITATION_FORMAT` immediately after `matText`, before the `mode === "plain"` return. Subtract its length from the context `room` budget so `tests/study-doctrine-caps.test.ts` still passes. `studyTools` tool descriptions already teach the tools; do not duplicate the long format there.

## UI / UX design
- Nothing new to lay out: the existing `CitationPill` is an inline chip, `mx-0.5`, `rounded-full`, `border-border`, `bg-card`, `px-2 py-0.5`, `text-xs`, `align-baseline`, `FileTextIcon size-3`, `label.replace(/^\(|\)$/g, "")`. Keep that geometry.
- States: inactive `text-foreground` with `text-muted-foreground` icon; hover `bg-accent`; focus `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring`; pressed uses the native button state. No tooltip besides `title="Open in side panel"`.
- Click: `openMaterial(materialId, page)` opens the side panel if closed, or focuses the existing tab and bumps `nonce` so `PdfReaderView` re-jumps to `?page=N`. No navigation away from the chat, no new window.
- Empty/loading/error: before `/api/study/library` resolves, `materials` is empty and citations render as plain text; a fetch failure keeps them plain text. No spinner or error chip.
- Narrow screens: the side panel already becomes a full-width `fixed inset-y-0 right-0 z-40` overlay under 900px; the chip behaves identically there.
- Theme tokens only: `border-border`, `bg-card`, `bg-accent`, `text-foreground`, `text-muted-foreground`, `ring-ring`. No glass, blur, drop shadow or raw colour values.

## Agent-facing wording
- Plain study chats: replace line 3 of `study-chat-prompt.md` with a sentence that keeps "check the files first", says "Cite them exactly as `(exact file name, p. N)`", and says "Never invent a citation". Do not add a second format anywhere else.
- Study block: the `STUDY_CITATION_FORMAT` paragraph is emitted for `teach`, `practice` and `plain` modes, after the Materials list and before the mode-specific doctrine. It must stay byte-identical across calls for prompt caching.
- Tool output: append `STUDY_TOOL_CITE_HINT` on its own final line to the strings returned by `lookup` and `read` in `studyContributions`. Do not alter the structured payloads, headings, `formatLookup` body, or `show_figure`'s existing `Shown: ... (fileName, p. N)` text.

## Edge cases
- Printed page numbers in `study_context` output ("printed p.4 → PDF page 6"): cite the PDF page 6, not 4.
- Duplicate/short file names: `findMaterial` prefers exact normalized match; the agent must use the exact Materials-list name to avoid the fuzzy fallback.
- `pp. 12-14` opens page 12; a range never opens the last page.
- Unknown material, page 0, page > `pageCount`, or a citation inside a fenced code block stays plain text.
- Saved citations in old transcripts render with the same chip once the subject library contains a matching material; no migration or re-write of stored messages.

## What must NOT change
- `CitationMatch`, the `lh-cite` token grammar, `findMaterial`, `findCitations`, `linkCitations`, `CitationPill`'s click target, `panelReducer`, `PdfReaderView`, or `/subjects/<sid>/read/<material>?page=N`.
- No new tool, no new agent tool schemas, no client-side re-parsing of assistant text, no changes to tutor-quote citations (`src/core/citations.ts`) or local-file path chips (`components/file-path-chip.tsx`).

- Regression: `findCitations("(Lecture 3 - Graphs.pdf, pp. 12-14)", mats)` resolves `m1` page 12 and `linkCitations` leaves fenced code untouched (already covered in `chat-side-panel.test.ts`; import the same helper for an integration assertion).
